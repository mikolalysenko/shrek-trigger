# Cartridge path and prototype budgets

The art and content patches execute as a native cartridge with the browser hooks disabled. JavaScript provides the emulator, diagnostics, checkpoint storage and developer commands. The builder retains 4 MiB HiROM when the assets fit, and expands to 8 MiB ExHiROM when measured player or reclaimed-data capacity requires it. Neither the IPS nor the expanded BPS contains a browser dependency.

## Rules for new features

1. Prefer existing event, battle AI, tech animation and graphics formats. Emit ROM records from a deterministic transform.
2. Prototype unsupported behavior at a verified CPU boundary. Record the source address, expected instructions, register widths, input/output WRAM, actor lifetime and cleanup behavior in a contract beside the feature.
3. Use finite state and integer, bounded buffers. Keep game state in a documented WRAM reservation only after checking ownership. Do not rely on DOM state, promises, host timers or unconstrained arrays for gameplay.
4. Represent effects with actual PPU tiles, palettes and OAM, respecting the current OBJ size, transparency, tile and scanline limits. Avoid a high-resolution canvas effect that cannot become a cartridge asset.
5. Port the finite-state operation to a 65C816 routine in allocated ROM. A hook becomes a JSL/trampoline that preserves P, DB, DP and all non-result registers, replays displaced instructions and restores the original timing contract. NMI work stays limited to bounded transfers.
6. Test the browser prototype and native implementation against the same inputs, WRAM outputs, actor positions, palette ownership and completion state. Test interrupted effects, death, transitions and save/load.

## Resource ceilings

- ROM: 4,194,304 bytes when content fits; 8,388,608 bytes for the measured cast expansion described below. Executable code and compressed resources remain in the original 4 MiB. Builds reject out-of-range, overlapping or unowned writes.
- PC art: four 16×16 OBJ cells per frame, 32×32 pixel canvas, twelve opaque colors plus transparency. Tile zero is reserved blank.
- Current replacements add **zero WRAM and zero VRAM allocation**. The swamp clones an existing tile bank and reuses the existing home collision and entrances.
- Native palettes use 15-bit SNES colors. No interpolated pixels are used on the game canvas.
- Event trace: at most 256 entries. High-frequency NMI and opcode events use counters, not growing logs.
- Checkpoints: one explicit browser slot and one return-from-jump slot; no rolling full-state snapshots.
- The build reports original per-character graphic capacities, reclaimed ROM allocations and remaining space. Reclaimed PC tails follow rewritten frames. Replaced NPC/enemy resources require all aliased pointer entries to be rewritten; replaced event packets require a unique global pointer. Exactly adjacent proven spans are combined within their bank; gaps remain reserved. A sizing pass measures every resource. Deterministic subset packing fills proven spans without crossing a bank; a second compilation uses the final addresses, and any larger relocated event triggers a new plan before a ROM is emitted. The index lookups permit reclaiming only the exact vacated player-assembly tails. Retired music packets also require unique full-pointer ownership and replacement of their source pointers.
- Replaced dialogue strings are reclaimed only after all identified owners have new B8 tables. The audit preserves original tables, live suffixes, direct pointers, unreferenced gaps and non-narrative banks. All 513 global event entries participate in alias checks. Numeric dialogue controls read a separate argument stream; control-aware extents preserve inline zero operands. See [trial-and-prison.md](trial-and-prison.md#native-text-and-storage).
- Native NPC sprite graphics share the existing 32 KiB field heap. Horizontal tile sharing and stable torso tiles avoid needless duplicate data. Area tests detect the cartridge’s fatal-error loop; remaining campaign scenes still need their own heap checks.

Do not expand the ROM or reserve additional runtime memory just to avoid a content audit. If a proven feature exceeds the available space, measure the need and update this budget before changing the mapper or cartridge layout.

## Measured cartridge expansion

The frozen supporting and ICP raster batch needs 42,113 additional compressed bytes, against 4,690 bytes free in the last 4 MiB review build. Pinocchio’s complete 30,912-byte player bank also fails the joint native-bank placement beside anchored Puss. These are measured content requirements; expanding ROM does not increase the 32 KiB NPC heap, OBJ cells, palettes, WRAM or VRAM.

The conservative ExHiROM layout follows Secret of Goku’s cartridge conversion. The first 4 MiB retains executable code, event programs and assemblies. Most compressed resources remain there; selected complete graphics packets may use explicitly owned extended data spans. The second half starts as an exact mirror; raw player/NPC tiles and selected compressed packets occupy only the lower halves of full banks 40–7D. All upper-half mirrors, reset vectors and absolute low-bank ROM reads remain intact. This mapping matches [Snes9x’s extended HiROM mapper](https://github.com/snes9xgit/snes9x/blob/master/memmap.cpp) and [bsnes’s EXHIROM-RAM board](https://github.com/bsnes-emu/bsnes/blob/master/bsnes/target-bsnes/resource/system/boards.bml). Both headers declare mapper35 and size13, with checksums over the full 8 MiB. SRAM maps only at 20–3F/A0–BF:6000–7FFF.

Puss stays at D3:0000. Other complete player streams of at most 32 KiB move into owned extended banks; larger streams retain a proven original region. Pointer redirection precedes reclaiming the old allocations. The 157-byte field helper at C0:E6B6 preserves the D5 fast path and copies exactly sixteen words through the existing long source pointer for extended banks. It preserves X, DB, DP and stack depth, then rejoins the native epilogue to restore Y and advance the WRAM port. D2/D3/D4/7F paths, battle and menu readers retain their original logic. No new runtime buffer is reserved.

The first blank tile at D2:0000 has an additional absolute consumer: the cinematic engine copies its zeros into callback tables. Its 32 bytes remain reserved even after Farquaad's graphics move. The allocator verifies this shared data and excludes it from reclaimed pools. The full Dragon approach regression exercises these copies through the original recovery dialogue; see [the diagnosis](character-art.md#shared-cinematic-blank-tile).

The builder’s default `cartridge:'auto'` retries only typed capacity failures. `npm run build -- --cartridge=hirom` requires the original layout; `--cartridge=exhirom` explicitly exercises expansion. Tests can use `SHREK_TEST_CARTRIDGE=exhirom`. The audit records the expansion reason, actor placement, free original and extended bytes, and native copier address. BPS encodes preserved bytes with SourceRead and the second-half mirrors with TargetCopy, following the [public-domain BPS specification](https://github.com/Alcaro/Flips/blob/master/bps_spec.md). The build removes a stale patch of the other format.
